# 按问题选择讲解方式

本文件只在 SKILL.md 指定的情形下读取，以下情形是选择项，不是每篇依次完成的章节。

## 分别理解多个易混对象

触发：用户想先分别弄懂两个或多个独立对象，而非只问它们的差异。

先让对象 A 能被单独辨认，再讲对象 B，最后解释关系。每个对象用最小定义、核心机制与具体例子建立模型；只补会影响机制理解的背景。不要靠“另一个不是这样”定义当前对象。

若只问差异或关系，直接在相应比较点补最小定义即可；名称可能是别名时先确认身份。区分先后、影响、因果、继承与相似，不能由时间相邻推断因果。

## 形成背景影响机制理解

触发：不交代“为什么出现”，读者就无法理解这个机制或做法。

恢复最短因果链：原有状态 → 变化或压力 → 原做法的缺口 → 新做法怎样回应 → 可观察结果。年份、地点与人物只有在改变条件时才有解释价值。

背景与当前问题无关时省略；不能为完整感虚构形成史。前提和结果共同构成一个认知台阶时放在一起，不拆成孤立大卡片。

## 蒸馏用户的梳理过程

触发：用户明确要求整理追问过程，或选中的一次认知修正本身就是讲解重点。

从实际对话与账本选取改变模型的关键节点，用“卡在哪里 → 哪个解释补上缺口 → 现在能区分或判断什么”呈现。合并重复追问，阅读顺序服从知识依赖而非聊天时间。

只展示有证据的修正，不推断用户未表达的感受或掌握程度。最终模型与梳理路径可以结合，不另写一遍同义总结；历史修订、作者操作日志和测试管理信息不自动进入正文。
